# Mamaearth Returns & Growth Intelligence Pipeline

A three-layer data analytics and intelligence pipeline built to investigate, quantify, and report on return rates and revenue anomalies across Mamaearth's H1 2026 orders.

The project bridges three engineering stages into a connected workflow:
1. **Relational Data Layer (SQL / SQLite)**: Stores schema definitions, loads raw transaction data, and executes analytical baseline reports.
2. **Analysis & EDA Layer (Python / Pandas)**: Cleans inconsistent records, handles missing values, eliminates duplicate orders, isolates bulk outliers, and tests business hypotheses.
3. **Executive Narrator Layer (Google Gemini / SCR Framework)**: Ingests verified numerical findings and produces a structured business narrative for regional operations and finance leaders.

## Execution Guide

Run the pipeline layers in sequential order from the repository root directory.

### Layer 1: Relational Data Layer (SQL)

You can build the database and execute all 9 business queries using either Python's built-in SQLite engine or the SQLite command-line tool.

#### Option A: Using Python (Recommended - No installation required)

Python includes SQLite by default. Run this single command to create `mamaearth.db` and run all queries:

```bash
python -c "import sqlite3, pathlib; conn=sqlite3.connect('mamaearth.db'); c=conn.cursor(); [c.executescript(pathlib.Path(f).read_text(encoding='utf-8')) for f in ['sql/schema.sql','sql/seed_data.sql','sql/reports.sql']]; print('SQLite database built and all reports executed successfully.')"
```

Verify seeded table row counts:

```bash
python -c "import sqlite3; conn=sqlite3.connect('mamaearth.db'); c=conn.cursor(); print('Customers:', c.execute('SELECT COUNT(*) FROM customers').fetchone()[0]); print('Products:', c.execute('SELECT COUNT(*) FROM products').fetchone()[0]); print('Orders:', c.execute('SELECT COUNT(*) FROM orders').fetchone()[0])"
```

#### Option B: Using SQLite Command-Line Interface

If `sqlite3` installed in the system:

```bash
sqlite3 mamaearth.db < sql/schema.sql
sqlite3 mamaearth.db < sql/seed_data.sql
sqlite3 mamaearth.db < sql/reports.sql
```

Row count verification:
- `customers`: 45 rows
- `products`: 16 rows
- `orders`: 180 rows (raw data prior to deduplication)

`sql/reports.sql` contains queries `(a)` through `(i)`. Each query is preceded by its exact output comment for direct verification.

### Layer 2: Data Wrangling, EDA & Visualizations

#### 1. Run Data Cleaning & Exploratory Analysis
Execute `clean_and_eda.py` to run Tasks 1 through 10:

```bash
python analysis/clean_and_eda.py
```

This step executes:
- **Casing standardization**: Unifies 7 messy payment strings into `CARD` (70), `UPI` (55), and `COD` (55).
- **Deduplication**: Identifies and drops 5 duplicate rows caused by checkout double-submits (`O0176`–`O0180`), reducing order count to 175.
- **Missing value imputation**: Fills missing discount values with `0%` and unrated orders with the median rating (`3.0`).
- **Revenue reconciliation**: Confirms the ₹2,501.90 delta between raw revenue (₹99,860.20) and clean revenue (₹97,358.30) comes solely from the 5 duplicate transactions.
- **Outlier isolation**: Detects 2 bulk transactions in January (`O0011` with qty 25, `O0098` with qty 30) using the 1.5 × IQR rule.
- **Risk segmentation**: Quantifies that Cash-on-Delivery (COD) orders suffer a 44.4% return rate overall, spiking to 54.5% in Tier-2 cities.
- **Time-series normalization**: Adjusts January revenue down from an inflated ₹29,582.10 to ₹11,637.10, establishing March as the genuine peak month at ₹20,318.90.
- **Data export**: Saves all computed findings to `narrator/findings.json`.

#### 2. Generate Visualizations
Execute `visualize.py` to generate standalone charts:

```bash
python analysis/visualize.py
```

Outputs created in `visualizations/`:
1. `return_rate_by_payment.png`: Bar chart demonstrating COD returns (44.4%) running at triple the Card return rate (14.7%).
2. `monthly_revenue_trend.png`: Line chart depicting monthly revenue trajectories and highlighting the outlier-corrected March peak.

### Layer 3: GenAI Executive Narrative

Execute `generate_narrative.py` to synthesize the findings into a Situation-Complication-Resolution (SCR) report:

```bash
python narrator/generate_narrative.py
```

#### Running Modes:
- **Online Mode (Google Gemini API)**: If a `GEMINI_API_KEY` is present (or set as an environment variable), the script calls Google Gemini (`temperature=0.0`, request timeout enforced) to draft the report. On successful generation, the narrative automatically saves to `narrator/sample_output.txt`.
- **Offline Fallback Mode (Deterministic)**: If no API key or network connection is available, the script catches the condition gracefully and renders the report using a built-in deterministic template. The pipeline never crashes due to missing credentials.

#### API Key Configuration:
Set your key before running:

```bash
# Windows Command Prompt
set GEMINI_API_KEY=your_key_here

# Windows PowerShell
$env:GEMINI_API_KEY="your_key_here"

# Linux / macOS
export GEMINI_API_KEY="your_key_here"
```
#### Automated Accuracy Verification
At the end of every run, `generate_narrative.py` runs a numeric checklist that verifies all five mandatory metrics exist in the narrative text:
1. Cleaned revenue: `97,358.30`
2. COD return rate: `44.4%`
3. COD + Tier-2 return rate: `54.5%`
4. Reconciliation delta: `2,501.90`
5. True peak month and revenue: `March` with `20,318.90`

The script also validates the saved sample `narrator/sample_output.txt`, providing instant pass/fail verification for grading.
